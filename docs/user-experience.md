# 사용자 경험과 화면 상호작용

이 문서는 현재 작업 트리의 React UI를 기준으로 사용자 흐름, 상태 표현,
반응형 레이아웃과 접근성 계약을 설명합니다. 운영 배포 여부와 마지막 검증
스냅샷은 [구현·운영 현황](./current-state.md)에서 별도로 관리합니다.

## 1. 화면 목표

사용자는 최초 한 번 개인화 정보를 설정한 뒤 출발지와 목적지만 선택해 실제
대중교통 기반 건강 경로를 비교합니다. 현재 걸음은 헤더에서 바로 고칠 수
있고 목표 걸음과 한 걸음 길이는 같은 요약 영역에서 확인합니다. 데스크톱은
왼쪽 탐색·결과 패널과 지도, 모바일은 헤더 요약·지도·하단 시트로 구성합니다.

## 2. 랜딩과 진입

- 첫 방문에는 전체 화면 인트로 애니메이션을 표시합니다.
- 2.2초에 본문을 드러내고 3초에 인트로를 종료합니다.
- 모션은 등고선, 노이즈 질감, 경로 선 그리기, 타이포그래피와 배경의 깊이
  이동으로 구성합니다.
- `prefers-reduced-motion`에서는 인트로를 재생하지 않고 본문으로 바로
  진입합니다.
- 건너뛰기 버튼과 자동 완료 모두 본문 포커스를 안전하게 복원합니다.
- 같은 브라우저 tab session의 새로고침에서는 완료 상태를 확인해 곧바로
  검색 화면을 표시합니다.
- 종료 전 400ms에는 인트로 경로가 주황색 본문 경로 문법으로 이어지며,
  서비스 내 `동작 줄이기`를 선택한 경우에도 인트로를 건너뜁니다.

### Route Pulse 상태

앱 루트는 `idle → editing-place → ready → calculating → results →
route-selected` 흐름과 독립적인 `error` 상태를 `data-ui-state`로
노출합니다. 검색 필드, CTA, 계산 안내, 카드와 지도는 이 상태에서만
강조를 파생하며 주요 레이아웃 위치는 바꾸지 않습니다.

상태 우선순위는 `calculating` → `error` → `editing-place` →
`route-selected` → `results` → `ready` → `idle`입니다. `route-selected`는
결과가 생겼다는 뜻이 아니라 사용자가 카드 선택이나 상세 열기로 현재 경로와
상호작용했다는 뜻입니다. 같은 루트에는 다음
파생값도 함께 노출해 CSS와 자동화가 컴포넌트 내부 상태를 추측하지 않게
합니다.

| 속성 | 값 | 의미 |
| --- | --- | --- |
| `data-ui-state` | 7개 `PlannerUiState` enum | 현재 작업 단계 |
| `data-experience-mode` | `guided\|compact` | 보조 설명 밀도 |
| `data-route-fit` | `none\|in-progress\|complete` | 선택 추천의 목표 달성 상태 |
| `data-reduced-motion` | `true\|false` | OS 또는 서비스 설정으로 모션 축소 여부 |
| `data-telemetry-consent` | `unknown\|granted\|denied` | 익명 사용성 지표 동의 상태 |

Route Pulse의 색은 역할이 고정되어 있습니다. 빠른 추천은 남색, 균형 추천은
청록, 목표 추천과 도보는 주황, 버스는 파랑, 지하철은 보라, 빨강은 오류에만
사용합니다. 같은 의미를 텍스트·아이콘·선 스타일로도 제공해 색만으로 상태를
판별하게 하지 않습니다.

## 3. 검색 패널

```text
출발지 [입력........................]
       [출발·도착 교환] [현재 위치]
목적지 [입력........................]
       [건강 경로 찾기]
```

이 세로형 검색 폼은 왼쪽 탐색 영역에 고정되며 지도 위에 별도 검색 패널을
띄우지 않습니다. 두 장소가 모두 확정되기 전에는 `건강 경로 찾기`를
비활성화합니다. 계산 중에도 폼을 유지하고 진행 상태와 결과는 바로 아래에
쌓습니다.

각 입력은 다음 상태를 가집니다.

1. 빈 값
2. 한 글자 입력
3. 자동완성 요청 중
4. 자동완성 결과
5. 자동완성 0건
6. 명시 검색 요청 중
7. 명시 검색 최종 0건
8. 공급자 오류
9. 결과 선택 완료

입력 후 300ms가 지나면 `scope=suggest`로 요청합니다. Enter 또는 검색
버튼은 즉시 `scope=resolve`로 요청합니다. 새 입력이 시작되면 이전 요청은
취소됩니다. 첫 결과를 자동 선택하지 않으며 사용자가 목록 항목을 선택해야
출발지 또는 목적지가 확정됩니다.

결과 항목은 장소명, 도로명 또는 지번 주소와 좌표 성격을 표시합니다.
학교 POI는 `캠퍼스 중심`, 주소 검색 결과는 `도로명 주소`, 이름에 정문·후문
등이 포함된 결과는 `출입구`로 구분합니다. NAVER 보완 결과는
`NAVER 주소` 라벨도 표시하며 상호명 검색을 대신하는 것으로 표현하지
않습니다.

## 4. 현재 위치

현재 위치 버튼의 흐름은 다음과 같습니다.

```text
브라우저 위치 권한
  -> WGS84 좌표 취득
  -> /api/v1/places/reverse
  -> 주소가 있으면 주소 Place 선택
  -> 주소가 없거나 일시 장애면 "현재 위치" 좌표 Place 선택
```

권한 거절과 위치 취득 실패는 검색 입력을 계속 쓸 수 있는 안내로 표시합니다.
지도 클릭을 통한 장소 선택은 포함하지 않습니다.

## 5. 지도

- NAVER Web Dynamic Map을 기본 배경으로 사용합니다.
- 선택한 추천의 도보·버스·지하철 leg를 서로 다른 선 스타일로 표시합니다.
- 출발, 도착, 첫 승차, 환승, 최종 하차와 탑승 예정 차량을 구분합니다.
- 운동 시작 마커는 하차 마커와 겹쳐 읽기 어려우므로 표시하지 않습니다.
- 접근·환승·목표 도보를 포함한 모든 도보 구간은 주황색 실선으로
  통일합니다.
- 버스 중간 정류장은 선 계산에만 사용하고 지도 마커로 표시하지 않습니다.
- 두 번째 이후 버스의 승차 지점은 `탑승`이 아니라 `환승`으로 표시합니다.
- 버스 선은 TAGO 정류장 순서를 Kakao Mobility Directions의 도로 vertex에
  매칭해 도로 굴곡을 따라 표시합니다.
- TAGO가 반환한 노선 전체 차량을 그대로 표시하지 않습니다. 선택한 각 버스
  구간에서 탑승 정류장에 가장 가까이 접근 중인 차량만 최대 1대 표시합니다.
- 이미 탑승 순서를 지난 차량과 정류장 순서를 알 수 없는 차량은 제외합니다.
- 차량 마커는 노선번호만 간결하게 표시하고 차량 좌표는 지도 자동 확대
  범위에 포함하지 않습니다.
- SDK 인증 또는 로딩이 실패하면 실제 추천 좌표로 SVG 경로를 표시합니다.
- NAVER SDK의 기본 로고·저작권 컨트롤은 유지합니다.
- 데이터 공급자 안내는 지도 위 칩이 아니라 왼쪽 패널 최하단의
  `데이터 제공: NAVER 지도 · KAKAO 장소/도보 · 국토교통부 TAGO 버스`로
  표시합니다.
- 지도 장애와 추천 데이터 장애를 서로 다른 상태로 안내합니다.

## 6. 추천 입력과 결과

최초 이용자는 만 나이·신장·체중·생물학적 성별·하루 목표 걸음을 모두
입력합니다.
계정은 만들지 않으며 원본 신체정보는 브라우저에만 저장합니다. 직접 보폭
입력이나 20m 보행 측정은 제공하지 않습니다.

- 생물학적 성별은 연구식의 입력이므로 남성 또는 여성 중 하나를 선택하기
  전에는 저장 버튼을 활성화하지 않습니다.
- 적용 범위는 만 18~90세, 신장 120~220cm, 체중 30~200kg입니다.
- 입력이 유효하면 연구 기반 예상 한 걸음 길이를 cm 단위로 즉시 표시합니다.
- 하루 목표는 1~100,000걸음이며 기본값은 8,000걸음입니다.
- 저장 후 헤더 중앙에는 `현재 걸음`, `목표 걸음`, `개인화 한 걸음`만 작게
  표시합니다. 현재 걸음은 Enter 또는 포커스 이탈 때 반영하며 잘못된 값은
  이전 유효값을 유지하고 `aria-live` 오류를 안내합니다.
- 목표와 프로필은 `개인화 한 걸음` 수정 동작으로 다시 열 수 있습니다.
- `저장 정보 삭제`는 프로필과 선호를 지운 뒤 필수 온보딩을 다시 표시합니다.
- BMI 30 이상이면 적용 연구 범위 밖일 수 있다는 오차 안내를 표시합니다.

장소·현재 걸음·목표·개인화 값이 바뀌면 기존 추천을 즉시 폐기합니다. 추천
요청에는 장소, 현재·목표 걸음, 파생된 한 걸음 길이와 모델 버전만 보내며
마감시간이나 추가·안전 여유시간을 사용자에게 묻지 않습니다.

추천 중에는 시간이 지나면 완료된 것처럼 보이는 가상 단계를 표시하지
않습니다. 실제 요청이 진행 중이라는 단일 경로 추적 표시만 사용하고,
8초보다 길어지면 교통 정보 응답 지연과 장소 수정 가능성을 같은 영역에서
설명합니다. 결과는
다음과 같이 단계적으로 공개합니다.

1. 기본 카드에는 유형, 총 소요시간, 예상 도착, 이동수단 순서와 비중,
   도보 시간·거리, 환승, 예상 걸음과 목표 달성률만 표시합니다.
2. 운행 경고는 `운행 안내 n건` 안에 기본 접힘 상태로 표시합니다.
3. 카드를 선택하면 지도 경로만 즉시 동기화하며 이동 단계는 자동으로
   펼치지 않습니다.
4. 카드별 `자세히`를 누르면 선택 경로의 추천 이유, 요금, 전체 도보·버스
   이동 단계, 승하차 정류장과 도착 정보가 나타납니다.
5. 다른 카드를 선택하면 열려 있던 상세를 닫고, 카드의 `접기` 또는 상세
   제목의 `간략히`를 누르면 다시 비교 상태로 돌아갑니다.
6. 남은 목표가 있으면 목표 경로를 기본 선택하고, 목표를 이미 달성했으면
   빠른 경로를 기본 선택합니다.
7. 비선택 지도 경로는 0.18, 카드 hover/focus 경로는 0.55, 선택 경로는
   NAVER 지도에서 0.95 불투명도로 비교 맥락을 유지합니다. SVG 복구 지도는
   선택 경로를 1.0으로 표시합니다.
8. 결과 카드는 80ms 간격으로 나타나며 100% 이상 목표 달성은 700ms 이하
   1회성 주황 피드백만 표시합니다.

`자세히`로 상세를 열면 결과 패널이 상세 시작 지점으로 이동합니다. 사용자의
`prefers-reduced-motion` 설정이 켜져 있으면 즉시 이동합니다.

## 7. 반응형 구조

- 1024px 이상: 왼쪽 탐색·결과 패널과 넓은 지도 작업 영역
- 768~1023px: 왼쪽 패널을 유지하고 헤더와 지도 비중을 조정
- 767px 이하: 헤더 두 번째 행의 3열 걸음 요약, 지도와 스크롤 가능한 하단 시트
- 320px에서도 가로 스크롤 없이 핵심 입력과 버튼 사용 가능

## 8. 접근성

- 검색 입력은 combobox/listbox/option 관계를 제공합니다.
- 키보드로 위·아래 이동, Enter 선택 또는 명시 검색, Escape 닫기를 지원합니다.
- 로딩·0건·위치 결과는 `aria-live`로 알립니다.
- 아이콘 버튼은 모두 한국어 접근성 이름을 가집니다.
- 추천 선택 버튼은 `aria-pressed`, 상세 버튼은 `aria-expanded`와
  `aria-controls`로 선택·펼침 상태를 구분합니다.
- 추천 카드 안에 버튼을 중첩하지 않고 선택과 상세 열기를 독립된 버튼으로
  제공합니다.
- 색만으로 경로 유형과 경고를 구분하지 않습니다.
- 포커스 표시와 최소 터치 영역을 유지합니다.
- OS 설정 또는 서비스의 `동작 줄이기` 중 하나라도 켜지면 경로 드로잉,
  위치 이동, 패널 슬라이드와 펄스를 제거합니다.

## 9. 오류 메시지 원칙

- 입력 오류는 해당 행동을 수정할 수 있는 문장으로 안내합니다.
- Kakao/NAVER/TAGO의 원문 오류와 자격 증명은 브라우저에 노출하지 않습니다.
- 주소 보완 성공은 오류로 표시하지 않습니다.
- 두 주소 공급자가 정상 0건이면 다른 이름이나 주소를 요청합니다.
- 401/403 설정 오류는 운영 readiness와 서버 로그에서 명확히 구분합니다.
- 경로 계산 일부가 실패해도 비교 가능한 실제 후보가 있으면 경고와 함께
  결과를 제공합니다.
- 최대 확장 범위 안에 운행 정류장이 없으면 정문이나 도로명 주소 선택을
  안내합니다.
- 운행 정류장은 있지만 직행 또는 1회 환승 연결이 없으면 지원하는 연결
  범위를 명시합니다.

## 10. 브라우저 상태 저장

- `chimap:intro-seen-v1`: sessionStorage, 현재 tab session의 인트로 완료
- `chimap:preferences`: localStorage, version 3 필수 개인화 프로필·하루 목표·
  현재 걸음·현재 걸음의 한국 날짜·마지막 장소
- `chimap:ui-experience-v1`: localStorage, 추천 성공 횟수·안내 밀도·
  모션 설정·익명 지표 동의

version 2는 프로필·목표·마지막 장소를 이전하고 현재 걸음을 0으로 시작합니다.
version 1 또는 손상된 값은 필수 프로필이 없으므로 최초 온보딩을 다시
요구합니다. 새 저장은 항상 version 3으로 기록합니다. 현재 걸음은 한국 날짜
기준 당일 새로고침에서만 복구하고 자정·앱 재활성화·날짜 변경 감지 시 0으로
초기화하면서 기존 추천도 폐기합니다. 서버에는
원본 프로필이나 이 브라우저 상태를 전송해 저장하지 않고, 추천 요청에는
파생된 `walkingMetric`만 포함합니다. 저장된 Place도 다음 추천 요청을 보내기
전 사용자가 입력을 수정하면 즉시 선택 해제됩니다.

안내 밀도 `auto`는 추천 성공 0~2회에 `guided`, 3회부터 `compact`를
사용합니다. compact는 도움말만 줄이며 검색 필드, 버튼, 카드 정보와 지도
범례 위치를 바꾸지 않습니다. 설정에서 자동/자세히/간결하게, 시스템
모션/동작 줄이기, 학습 상태 초기화를 언제든 선택할 수 있습니다.

익명 사용성 정보는 명시적으로 허용한 경우에만 전송합니다. 이벤트는
허용된 화면 상태, 성공·실패 결과와 네 구간의 시간 bucket만 포함하며
검색어, 좌표, 장소·노선 ID, 신체정보, 세션·사용자 ID와 정확한 시각을
포함하지 않습니다.

동의가 `unknown`이면 인트로 뒤에 간단한 선택 배너를 표시합니다. 거부하거나
나중에 설정에서 철회하면 이벤트 요청을 보내지 않습니다. 허용한 경우에도
`POST /api/v1/ui-events`의 strict enum만 전송하며 성공 시 본문 없는
`204 No Content`를 받습니다. 학습 상태 초기화는 추천 성공 횟수와 표시
설정만 기본값으로 되돌리고 이미 선택한 동의 상태는 유지합니다.

화면 설정 dialog를 열면 닫기 버튼으로 포커스를 옮기고 Escape 또는 배경
클릭으로 닫을 수 있습니다. dialog가 열린 동안 뒤의 앱은 `inert`로 두어
키보드 포커스가 배경 컨트롤로 빠지지 않게 합니다.

## 11. 검증 기준과 배포 경계

다음은 새 UI를 배포할 때 공개 도메인에서 한 흐름으로 검증해야 하는 release
gate입니다.

1. 인트로 건너뛰기
2. 필수 만 나이·신장·체중·생물학적 성별·하루 목표 입력과 프로필 저장
3. 한국과학기술원·대전역 검색과 직접 선택
4. 추천 카드 3종과 기본 상세 닫힘 확인
5. `자세히` 열기, 경로 변경 시 닫힘, `접기` 확인
6. NAVER 지도 준비 상태와 경로선
7. 차량 마커 수가 선택한 버스 구간 수 이하인지 확인
8. 상세 이동 단계
9. 새로고침 후 version 3 프로필·장소·당일 현재 걸음 복구
10. 1440/768/390/320px 가로 overflow 없음

현재 구현은 로컬 production build를 Chromium의 1440·768·390·
320px에서 열어 헤더 충돌·검색 폼·가로 overflow를 확인했고, 결정적 웹
테스트 39개를 포함한 전체 97개 테스트, typecheck와 production build가
통과했습니다. 2026-07-26 15:12 KST에는 공개 JavaScript asset 교체와 같은
네 화면 폭의 공개 Chromium smoke도 통과했습니다. 15:21 KST에는 최초 설정,
장소 검색, 자동 추천, 상세 보기, v3 복원과 실제 공급자 회귀를 포함한 공개
E2E 2개도 통과했습니다. 운영 수치는
[구현·운영 현황](./current-state.md)을 기준으로 합니다.

별도 API 회귀 흐름에서 KAIST 본원 `캠퍼스 중심` 좌표→대전 갤러리아를
조회하고, 500m를 넘는 첫 승차 Kakao 도보와 TAGO 버스 추천이 반환되는지도
확인합니다.
