# 추천 알고리즘

## 입력

추천 요청은 출발지, 목적지, 도착 마감시간, 현재 걸음, 하루 목표, 최대 추가
허용시간, 보폭, 안전 여유시간을 받는다.

서버는 먼저 다음을 거부한다.

- 출발지와 목적지의 직선거리가 50m 미만
- 마감시간이 과거이거나 현재부터 6시간 초과
- 안전 여유시간을 빼면 유효한 미래 마감이 남지 않는 경우
- 공유 Zod 계약의 숫자·좌표·문자열 범위를 벗어난 입력

## 걸음 계산

```text
남은 걸음 = max(하루 목표 - 현재 걸음, 0)
목표 도보거리(m) = 남은 걸음 × 보폭(m)
경로 예상 걸음 = round(경로 도보거리 ÷ 보폭)
이동 후 예상 총 걸음 = 현재 걸음 + 경로 예상 걸음
```

걸음 수는 건강 측정값이 아니라 거리 기반 추정값이다. 하루 목표 달성률과
부족분 충족률은 100%에서 잘라 UI가 과도하게 표시되지 않도록 한다.

## 후보 생성

### 1. 기본 경로

출발지와 목적지 각각 500m 안에서 `cityCode`와 `nodeId`가 연결된 TAGO
정류장을 최대 8개 찾는다. 정류장별 경유 노선의 교집합과 `nodeOrder`를
검사해 직행을 만들고, 설정이 허용하면 노선 간 동일 정류장 또는 100m 이내
환승점을 이용한 1회 환승도 만든다.

버스 승차시간은 경유 정류장 좌표 거리, 평균 20km/h, 중간 정류장당 25초로
추정한다. 탑승 정류장의 실시간 도착정보가 있으면 대기시간에 반영하고,
없으면 배차간격의 절반 또는 기본 10분을 사용해 예상값임을 표시한다.
정류장까지/하차 후 걷기는 설정상 4.5km/h 직선 구간으로 계산한다. 이렇게
만든 경로를 소요시간 순으로 정렬하고 가장 빠른 것을 baseline으로 사용하되,
다른 기본 경로도 후보에 포함한다.

이미 목표를 달성했다면 여기서 운동 후보 생성을 중단한다.

### 2. 조기 하차 후보

각 기본 경로의 마지막 버스 또는 지하철 구간에서 목적지 전 최대 6개
정류장명을 모은다. 중복을 제거하고 최대 12개를 장소 검색으로 해석한다.
현재 live provider는 버스 leg를 TAGO에서 만들고 정류장명 좌표 해석에는
Kakao 장소 검색을 사용한다.

정류장 장소의 신뢰도는 다음 요소로 계산한다.

```text
0.55 × 이름 유사도
+ 0.20 × 교통 카테고리 일치
+ 0.25 × 원래 경로선 근접도
```

신뢰도 0.58 미만이거나 원 경로선에서 1.5km 넘게 떨어진 결과는 버린다.
목표에 필요한 추가 도보거리와 목적지까지의 직선거리가 가까운 순으로 최대
4개를 선택한다.

각 장소에 대해 `출발지 → 조기 하차 지점` 대중교통과 `조기 하차 지점 →
목적지` 도보를 병렬 조회해 결합한다.

### 3. POI fallback

유효한 운동 후보가 2개 미만이면 목적지 주변의 공원, 광장, 역, 공공시설을
검색한다. 쇼핑, 병원, 학교, 아파트 등 운동 우회 지점으로 부적절한
카테고리는 제외하고 최대 2개를 같은 방식으로 결합한다.

### 4. 연결성 검증

- 대중교통 끝점과 도보 시작점 차이: 최대 120m
- 도보 끝점과 실제 목적지 차이: 최대 250m
- 결합한 도보 leg는 `isExerciseSegment=true`

path가 비어 연결성을 확인할 수 없는 후보는 사용하지 않는다. 일부 후보만
실패하면 전체 요청을 실패시키지 않고 `PARTIAL_CANDIDATE_FAILURE` 경고를
남긴다.

## 시간 필터

```text
예상 도착 = 요청 처리 시각 + 후보 소요시간
유효 마감 = 사용자 마감 - 안전 여유시간
추가시간 = 후보 소요시간 - baseline 소요시간
```

예상 도착이 유효 마감보다 늦거나, 추가시간이 사용자의 최대 추가
허용시간보다 크면 후보를 제거한다. 미래 시간표를 예측하지 않으며 모든
경로는 “지금 출발” 기준이다.

## 균형 점수

BALANCED 정렬은 낮을수록 좋다.

```text
stepError       = 목표 남은 걸음과 후보 걸음의 정규화 오차
timePenalty     = max(추가시간, 0) / 최대 추가 허용시간
transferPenalty = 환승 횟수 / 3
connection      = 정류장 해석과 연결 간격의 불확실성

score =
  0.55 × stepError
+ 0.30 × timePenalty
+ 0.10 × transferPenalty
+ 0.05 × connection
```

각 항은 0~1로 제한한다. 건강 목표 오차를 가장 중요하게 보되 시간 비용이
뒤따르도록 설계한 MVP 휴리스틱이다.

## 중복 제거와 최종 선택

다음 조건을 모두 만족하면 두 후보를 같은 경로로 본다.

- 버스·지하철 노선 서명과 환승 횟수 동일
- 도보거리 차이 250m 미만
- 소요시간 차이 3분 미만
- 단순화한 경로 shape가 유사

최종 선택 순서는 다음과 같다.

1. `FAST`: 가장 짧은 소요시간, 동률이면 짧은 도보거리
2. `GOAL`: 남은 걸음과 예상 걸음의 절대 차이가 가장 작고 FAST와 다른 경로
3. `BALANCED`: 균형 점수가 가장 낮고 앞선 선택과 다른 경로
4. 응답 순서는 비교 편의를 위해 FAST, BALANCED, GOAL

충분히 다른 후보가 없으면 1~2개만 반환하고 빈 카드를 만들지 않는다. 목표를
이미 달성한 경우에는 FAST만 반환한다.

## 호출 예산과 실패 모드

한 추천 요청의 경로 조회는 대중교통 5회, 도보 4회, 총 9회를 넘지 않는다.
여기서 대중교통 1회는 내부적으로 주변 정류장·정류장별 노선·노선 상세·경유
정류장·도착 API를 여러 번 호출할 수 있으며 각 결과는 TAGO 전용 TTL과
single-flight로 보호된다. 장소 검색은 후보 해석에
필요하지만 경로 호출 예산에는 포함하지 않고 동시성 3 제한과 cache를
공유한다.

결과에는 추정값, 지금 출발 기준, demo 데이터, 부분 실패, 목표 미달,
다양성 부족을 명시적 warning으로 포함한다. 조건을 만족하는 경로가 하나도
없으면 `NO_ROUTE_WITHIN_DEADLINE`을 반환한다.

## 한계와 개선 방향

정류장 좌표를 이은 버스 polyline은 실제 도로 shape가 아니다. 현재 점수는
개인의 걷기 속도, 경사, 날씨, 접근성, 환승 안정성, 실제 지연을 학습하지
않는다. production 고도화 시 익명화된 선택 결과와 취소율로 가중치를
검증하고, 휠체어·경사·야간 안전 조건을 별도 hard constraint로 추가해야
한다.
